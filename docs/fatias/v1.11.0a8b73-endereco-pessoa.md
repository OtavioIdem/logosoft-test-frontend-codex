## 1. Objetivo

Quem cadastra Pessoas mantém os endereços dela, e sabe qual é o principal, que é o endereço usado na
nota. **O faturamento ainda não conclui depois desta versão**: o endereço nasce sem município
vinculado, e o vínculo é da `b74`, com outra permissão.

## 4. Armadilhas conhecidas desta fatia

- **A resposta só traz o endereço tocado (EP-5/EP-6).** Nunca atualize a lista com a resposta: releia a
  lista. Mandar `principal:false` no único principal volta `true`. Excluir o principal promove outro.
- **Todo erro é `PESSOAS_VALIDACAO` (400)**, inclusive endereço inexistente (EP-8).
- **A fixture E2E `tests/e2e/fixtures/logosoft.ts:741`** responde a qualquer `/api/pessoas*` com o array de
  pessoas, inclusive o `GET …/enderecos`. O E2E precisa de rota própria registrada antes.
- **`NotaFiscalErroCadastroPanel.test.tsx:48`** exige `null` para `DestinatarioSemEnderecoFiscal`. Ele
  continua verde, porque o link é da `b74`.
- **Os agentes de teste da b69/b70 entregaram teste vácuo.** Toda prova vermelha precisa ser executada. Git que
  altere a árvore é proibido. Restaure com `cp` e confira com `cmp`.
- **Varredura transversal antes do QA**, com `grep -rl` pelos arquivos tocados: `pessoasApi`, `usePessoas`
  (18 consumidores) e `PessoaFormDialog`.
- **E2E só pela receita da porta 3411**, com o servidor encerrado no fim.

## 5. Critérios de aceite

Sessões: **S1** só `PESSOAS_CONSULTAR`; **S2** `PESSOAS_CONSULTAR` + `PESSOAS_GERENCIAR`.

| Id | Critério | Como se verifica |
| --- | --- | --- |
| AC-1 | Tipos e schemas cobrem os 9 campos de escrita (request `.strict()`) e a response inteira (não estrita), com cidade ≤ 120, UF entre as 27 e os limites do C# | unit de schema; gate de request |
| AC-2 | Na edição, a aba lista os endereços ativos da pessoa. Na criação, mostra o texto de "salve a pessoa" e faz 0 GET | componente |
| AC-3 | S1 vê a lista sem Novo/Editar/Principal/Excluir. S2 opera tudo. O diálogo de Pessoa continua abrindo só por quem gerencia (D102 não muda isso) | componente |
| AC-4 | Criar e editar enviam os 9 campos. Depois de qualquer mutação (criar, editar, principal, excluir), a lista é relida, e não remendada com a resposta | componente com request capturado + prova vermelha |
| AC-5 | O principal aparece marcado e a aba diz que ele é o endereço da nota. "Marcar principal" chama a rota e relê a lista. Excluir o principal mostra o aviso da promoção | componente |
| AC-6 | Editar com UF trocada e município vinculado mostra o aviso de remoção do vínculo. Cidade trocada com a mesma UF mostra o aviso de vínculo antigo. Sem vínculo, nenhum aviso | componente |
| AC-7 | O erro do backend aparece no `ApiErrorPanel` com code e traceId (o client preserva) | unit do client + componente |
| AC-8 | O gate de request cobre criar e editar endereço, com prova vermelha executada acusando um campo retirado pelo nome | gate_estrutural |
