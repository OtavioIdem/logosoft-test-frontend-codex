categoria que o backend guarda.

## 4. Armadilhas conhecidas desta fatia

1. **Renomear só o campo.** `statusBem` com o enum antigo de três valores faz o valor `2` virar
   "Bloqueado" para bem baixado. Por isso `D18` troca o enum inteiro.
2. **Guarda de Baixar herdada.** A guarda antiga aceita bem bloqueado; o domínio recusa
   (`BemPatrimonial.cs:198`). Copiar `[Ativo, Bloqueado]` com os nomes novos reproduz o erro.
3. **Default de categoria pelo número.** `initialBem` usa `CategoriaBem.Equipamento`, que hoje é `4`
   (Máquina no backend). Trocar só o import mantém o `4` se alguém escrever o literal. Tem de ser
   `CategoriaBemPatrimonial.Equipamento` (`5`).
4. **O teste de regressão da `c1` lê `origin/main`.** Hoje passa por coincidência (`origin/main` =
   `2c50771`); fica vermelho no `main` depois do merge do PR 16. `D19` fixa o SHA.
5. **Teste que lê o registro.** `risk.yaml`, `teste_que_le_o_registro`: a prova do gate não pode
   conferir o `allowlist.json`; tem de executar o gate.
6. **Afirmar total.** A prova é por nome, um a um, nos dois sentidos.
7. **Suíte completa.** Estoura o ambiente. Só `tests/unit/patrimonio*`, `tests/unit/gateContractFields*`,
   o teste de componente novo, e o recorte que o QA declarar.
