## 1. Objetivo

Na aba de Impostos, o operador passa a saber de onde veio cada linha (motor ou lançamento manual) e qual
delas compõe o total. No detalhe da nota, vê do que o total é feito — produtos, desconto, frete, seguro,
outras despesas, IPI, ICMS-ST e FCP-ST — e, com `FISCAL_GERENCIAR` e a nota alterável, define frete, seguro
e outras despesas.

## 4. Armadilhas conhecidas desta fatia

1. **A supressão só vale para três nomes.** `ValorEfetivoPorNomeImposto` é chamado só para `IPI`, `ICMS ST`
   e `FCP ST` (`NotaFiscal.cs:674-676`). Para os demais (ICMS, PIS, COFINS, ISS), nenhuma linha compõe
   `ValorTotal`. A UI não pode dizer "compõe o total" para uma linha de ICMS.
2. **A chave é (item, nome), e item pode ser nulo.** O agrupamento é por `ItemNotaFiscalId` (inclusive
   `null`, imposto da nota) dentro de linhas ativas do mesmo nome (`NotaFiscal.cs:684`). A normalização do
   nome (maiúsculas, trim) acontece em `AdicionarImposto` — o planner confere se o `nome` persistido e
   devolvido já vem normalizado, porque a comparação do frontend depende disso.
3. **Request de acessórios: o documento diz opcional, o record diz obrigatório.** Record posicional sem
   default (`NotaFiscalRequests.cs:104-107`). Mandar sempre os três, não negativos.
4. **O frontend não sabe hoje o que o backend chama de alterável.** `GarantirPodeAlterar` bloqueia
   Autorizada, Cancelada, Inutilizada, Denegada, Transmitida e Descartada (`NotaFiscal.cs:704`);
   `notaPodeEditarItens` libera só Rascunho e Validada (`fiscalUiUtils.ts:207`). Divergência a arbitrar,
   não a copiar.
5. **O override manual exige observação** (`ImpostoManualSemMotivo`), e o diálogo atual preenche
   "Imposto parametrizado manualmente." por padrão, com hint "O frontend não calcula imposto
   automaticamente nesta etapa." — mesma desinformação da legenda, e o padrão esvazia o motivo auditado.
6. **Linhas inativas.** Conferir no mapper se a resposta traz só linhas ativas. Se trouxer inativas, a
   regra da UI muda; se não, a UI não tem como mostrar o manual substituído, e não inventa.
7. **`valorIpi`, `valorIcmsSt` e `valorFcpSt` são opcionais no final do record** (default `0m`). Tipar como
   `number` obrigatório no response é afirmar mais do que o contrato garante; ler com fallback.
8. **Gate de contrato.** `valores-acessorios` não está no catálogo lido por `validate:backend-contract-map`
   (D22). O adendo é da sessão principal, antes do nó `tests`.
9. **Typecheck nos testes (E-1).** `target: es5`: sem `for...of` sobre `NodeList`, sem regex com flag `s`.
   O nó `tests` roda `npx tsc --noEmit`.
10. **Testes só do módulo.** `npx vitest run tests/unit/fiscal*.test.ts tests/components/<novos>`; nunca a
    suíte completa, nem `npm run test:unit -- <arquivo>`. E2E pela receita isolada, porta 3411, duas vezes.
11. **A fixture e2e é compartilhada.** Mudar `tests/e2e/fixtures/logosoft.ts` exige rodar de novo o
    `permissions.spec.ts`.
12. **Pendências herdadas da b55 para o `engenheiro-testes`:** QA3-2, QA3-3 e QA3-4 (plano da b55, §10).
    Entram no nó `tests` desta fatia só se o planner as incluir nominalmente; senão ganham destino.
